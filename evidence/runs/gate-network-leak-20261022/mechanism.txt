== 4. the mechanism
   Manager.init sets detected_cachyos when the machine's own os-release
   says CachyOS. sync_system_update() then consults the distribution's
   update notice BEFORE its database precondition: check() fetches the
   live notice, finds no saved answer in the operator's real cache, asks
   through the dispatcher — in the test machine there is no witness to
   answer "yes" — and the function returns RestartReport.empty. The test,
   written to prove "no sync databases -> SyncDbFailed", receives a
   success. Green at 08:35 and 13:55 while the fetch failed or the answer
   saved; red at 15:02 when a live notice served. The gate flipped on the
   internet, not on the tree. The replay in the Arch container never saw
   it: there /etc/os-release is not CachyOS, so the hook was never loaded.

== 5. the fix
   The database precondition is raised above the notice check: a manager
   with no sync databases cannot update a system, however the notice is
   answered — on any machine, with or without a network — and must say so
   before any interactive question. The same check syncDatabases() applies
   (alpm_get_syncdbs == null), now applied first. The notice's intent ("ask
   before downloading the database") is preserved: for a working
   installation the question still comes before any download.
   calix.Cli.Zig's install.zig:519 and upgrade.zig:635 consume the failure
   the caller needs: a transaction failure, not an empty success.
